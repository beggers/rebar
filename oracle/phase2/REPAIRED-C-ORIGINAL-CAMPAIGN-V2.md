# Safely recovered C correctness campaign, version 2

This source freeze is preparation, not a candidate result or a speed test.

The one permitted future run tests the repaired, first-party C implementation
against all 13 unchanged CPython correctness suites: 31,237 cases and the
same 13 explicitly named private waivers. It uses the corrected, independently
frozen version-3 original evaluator, version-7 suite worker, and version-9
aggregate runner. It never wraps or delegates matching to Python's `re`,
`_sre`, another candidate, or an external regular-expression package.

## Preserve every original result

The starting point is the exact published version-21 overview: 103 separately
owned evidence files, 108 authenticated history paths, and all 30 evidence
files from the earlier unsuccessful repaired-C run. Earlier failures remain
visible. A new run uses only the fixed label
`phase2-v9-original-p0` and refuses every pre-existing success, failure,
per-suite, aggregate, or outer-report destination.

All 13 original suite processes retain their complete standard output,
standard error, separately owned compressed records, publication receipts,
case denominators, and genuine matching differences. A matching claim is
accepted only after independently checking every saved suite against the
version-9 aggregate and the unchanged original CPython evidence.

If no genuine matching case was observed, matching and mismatch counts are
`NOT MEASURED`. An infrastructure failure is not a successful test or a
zero-mismatch result.

## Protect the existing native file

Before native activation, independently authenticate the corrected version-3
and version-9 read-only contexts, all three evaluator source pins, all four
published overview pins, the existing separately owned passing version-8
build archive and receipt, and the unchanged original C source and adapter.

The original native file must retain SHA-256
`075350a17d4909cd6f8dbe5e808e7b6444760f54bb60af013e0f812e22cfb7fd`,
149,976 bytes, device 2064, inode 430300, one hard link, and mode `0755`.

An outer recovery guard begins before parsing activation arguments,
authenticating live build evidence, promoting the native file, starting a
candidate process, or validating results. It discovers only the authentic,
freshly created version-5 recovery journal for this exact target and build.
When the version-9 runner has already restored the original, authenticate and
reuse its unique restoration receipt; never invoke recovery a second time.
After an early failure, use the frozen version-5 reportless recovery exactly
once when the authenticated journal proves a mutation needs recovery.

The outer report cannot be created unless the exact original native device,
inode, bytes, SHA-256, single-link identity, and `0755` permission have been
restored.

## Source-only gates

`--self-test` is entirely synthetic and blocks filesystem access, candidate
imports, subprocesses, activation, native libraries, networking, threads,
clocks, hidden cases, benchmark files, and holdout access.

`--verify-frozen-context` authenticates the entire frozen V3, V7, V9, and V21
history and the original native inode without activating or running any
candidate. Both gates must pass with ordinary and minimal
`PATH=/usr/bin:/bin` environments.

Candidate compatibility, qualified candidates, speed, memory, and final
holdout results are `NOT MEASURED`; the final holdout remains `NOT OPENED`.
No winner is selected.
