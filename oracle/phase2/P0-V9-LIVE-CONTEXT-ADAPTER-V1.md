That process passed its own argument namespace directly to the independently
frozen V7 worker. The V7 worker requires its own `runner_source_sha256`, so
the original process failed with `AttributeError` before any of the 13
original suites started. There were zero candidate workers. Compatibility,
matching failures, passing cases, speed, and memory were not measured.

## Minimal original-code bridge

Only a separately frozen and crash-safe future C V3 outer controller may
authorize the run mode. All three controller owners and all original live
V5 build, activation, journal, native, producer, runner, and worker owners
must be independently supplied and authenticated.

The adapter loads the exact original V9 runner and its genuine V7 worker
once. It derives the worker namespace using the unchanged V9
`actual_worker_arguments` for the first original suite. The first four
arguments must be the exact pinned Python executable, `-I`, `-B`, and the
original V7 worker path. The remaining unchanged arguments are passed to
the genuine V7 `parse_arguments` function.

A narrowly scoped worker proxy substitutes this genuine worker namespace
for the aggregate namespace in exactly one live-context call. A fresh
`types.FunctionType` uses the exact unchanged V9 aggregate code object and
a separate copied globals dictionary. Only its authenticated, single-use
worker loader differs. The original source, original function, original
module dictionary, V7 source, 13 independent worker processes, mismatch
recording, durable suite owners, journal recovery, original V9 aggregate
schema, and original V9 publication are preserved.

Frozen V3 and V9 context verification is permitted only before native
activation. The live bridge never calls a frozen context after promotion.
The original native target must be restored before result publication.
No standard-library regex engine, external regex package, other candidate,
fallback, clock, benchmark, final holdout, or generated final case is used.
